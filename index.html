Illustrative defect reports

The following are example report formats and hypothetical defects. Do not represent them as bugs found in a tested application.

Bug IDTitle / severityReproduction & expected vs actual
DEMO-BUG-001Cart subtotal fails to update after quantity change
High · hypothetical		Steps: add an item, open cart, change quantity from 1 to 2.
Expected: subtotal equals unit price × quantity.
Actual: example defect scenario: subtotal still shows the original quantity's amount.
DEMO-BUG-002Invalid discount code accepted
Medium · hypothetical		Steps: enter a code that is not configured and apply it.
Expected: code is rejected and total is unchanged.
Actual: example defect scenario: discount appears despite the code being invalid.
DEMO-BUG-003Repeated order submission creates duplicate orders
High · hypothetical		Steps: in a sandbox, submit once and rapidly click Place Order again.
Expected: one order and one intended payment only.
Actual: example defect scenario: two order references are created for one checkout attempt.
Good defect report checklist: concise title, environment/build, preconditions, reproducible steps, expected result, actual result, severity, priority, evidence, and reproducibility rate. Never test duplicate-payment scenarios against a real payment method.
